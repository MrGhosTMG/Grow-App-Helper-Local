Чтобы выполнить слияние в Git, вам нужно сначала переключиться на ветку, в которую вы хотите объединить изменения, а затем использовать команду git merge с указанием ветки, которую нужно слить. Например, чтобы слить ветку feature-branch в текущую ветку (например, main), нужно выполнить git checkout main и затем git merge feature-branch. Если возникают конфликты при слиянии, их нужно разрешить перед фиксацией изменений.
Пошаговая инструкция:
1. Переключитесь на целевую ветку:
Используйте команду git checkout <имя_целевой_ветки>, чтобы переключиться на ветку, в которую хотите влить изменения. Например, git checkout main переключит вас на ветку main. 
2. Выполните слияние:
После переключения на целевую ветку, используйте команду git merge <имя_ветки_для_слияния>, чтобы начать процесс слияния. Например, git merge feature-branch. 
3. Разрешите конфликты (если есть):
Если в процессе слияния возникают конфликты между изменениями в разных ветках, Git сообщит об этом. Вам нужно будет вручную открыть файлы с конфликтами, разрешить их, а затем добавить измененные файлы в индекс с помощью git add <имя_файла> или git add . (если нужно добавить все измененные файлы). 
4. Зафиксируйте изменения:
После разрешения конфликтов, зафиксируйте изменения с помощью команды git commit. Git автоматически предложит сообщение для коммита, но вы можете его изменить, добавив флаг -m и сообщение, например, git commit -m "Resolved merge conflicts". 
5. Отправьте изменения (если нужно):
Если вы работаете с удаленным репозиторием, вам нужно будет отправить изменения на сервер с помощью команды git push. Например, git push origin main отправит изменения в ветку main на удаленном репозитории. 
Пример:
Допустим, у вас есть две ветки: main и feature-branch. Вы хотите влить изменения из feature-branch в main.
Вы переключаетесь на ветку main:
Код

    git checkout main
Вы выполняете слияние:
Код

    git merge feature-branch
Если конфликты не возникают, Git автоматически создаст коммит слияния. Если возникают конфликты, вам нужно будет их разрешить и зафиксировать изменения.
Если вы работаете с удаленным репозиторием, вы отправляете изменения:
Код

    git push origin main
Важно:
Перед слиянием рекомендуется обновить локальную ветку main с удаленного репозитория, чтобы избежать конфликтов, вызванных изменениями, сделанными другими разработчиками. Для этого можно использовать команду git pull origin main. 
Если вы работаете в команде, убедитесь, что у вас есть разрешение на изменение целевой ветки, прежде чем начинать слияние.
Вместо git merge можно использовать git rebase, чтобы переписать историю ветки, но это более продвинутая техника, которая требует осторожности.
